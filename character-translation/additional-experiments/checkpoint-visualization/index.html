01 / Empirical Finding

Extended Optimization Did Not Recover Item Identity

The fixed qualitative evaluation panel shows no consistent convergence toward the target hat, top, or bottom under either prompt condition. Reporting this run transparently as a negative result prevents deceptive checkpoint selection.

02 / Diagnostic Evidence & Interpretation

Why Training Loss and Visual Behavior Diverged

Differentiating directly measured empirical indicators from mechanistic hypotheses. This run establishes failure under the embedding-only setup, not an intrinsic limitation of FLUX.

Ranked Mechanistic Explanations

Ordered by empirical strength of evidence in the audited run.

Ranked Mechanism Evidence in This Run Consequence Confidence
Embedding-only capacity bottleneck Only 30 token rows are retained; FLUX MMDiT and VAE remain frozen. The optimizer can redirect priors but cannot synthesize a missing sprite-rendering regime. High
Foreground-to-background imbalance The median target contains only 2.73% non-white pixels on a 256×256 canvas. MSE gradients are overwhelmed by blank canvas reconstruction rather than clothing features. High
Entangled three-item supervision Every example jointly presents hat, top, and bottom without isolated item views. Spatial evidence is not cleanly attributed to individual identifiers. High
Unequal text-encoder optimization CLIP-L drift reaches 104.2%; T5 drift reaches only 0.058%. Dual-conditioning collapses into an imbalanced, single-encoder update. Medium-High
Constant-rate over-optimization Loss plateaus early while CLIP-L drifts continuously through 90k. Additional iterations alter embeddings arbitrarily without checkpoint gating. Medium
03 / Revised Staged Protocol

Separating Domain Acquisition from Item Binding

A second unconstrained 90,000-step sweep is unwarranted. The revised protocol introduces capacity in stages with mandatory qualitative gates at each transition.

Stage 1

Establish Maple Prior

Train rank-16 FLUX transformer LoRA on 1,000 foreground-normalized targets for 1,000 steps with descriptive captions. Keep text encoders frozen.

Pass Gate: Centered full-body sprite structure appears reliably under domain prompt.
Stage 2

Bind Item Identifiers

Freeze accepted domain adapter. Learn FP32 CLIP-L identifier vectors from category-isolated and balanced examples. Keep T5 frozen.

Pass Gate: Modifying one identifier alters the intended region while other regions remain stable.
Stage 3

Joint Refinement

Jointly refine identifiers and small attention adapters with reduced learning rate. Sample qualitative panels every 250 steps.

Stop Rule: Terminate when visual panel plateaus; eliminate blind 90k training horizons.

Protocol Comparison: Previous Run vs. Revised Pilot

Factor Current Run Revised Pilot
Trainable capacity 30 CLIP-L + T5 token rows (embeddings only) FLUX transformer LoRA, rank 16 (shared prior first)
Image geometry 256² canvas; small sprite on white background 512² canvas; foreground occupies ≈75% extent
Text encoders CLIP-L and T5 embedding matrices in BF16 Frozen in Stage 1; FP32 CLIP-L identifiers in Stage 2
Optimization 90,000 steps, constant lr 5×10−4 1,000-step gate, LoRA lr 1×10−4
Selection Loss plus 3k-spaced post-hoc inspection Fixed visual panel audit every 250 steps

What Stage 1 Does Not Test

The domain-LoRA pilot does not claim item-specific inversion. It is a prerequisite test: if FLUX cannot reproduce the normalized Maple image domain with additional transformer capacity, identifier learning should not proceed on this backbone and preprocessing.
