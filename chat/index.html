Maple Chat: Evidence-Grounded Hybrid RAG & Knowledge Graph System

Retrieval supplies document evidence. A knowledge graph resolves names and stored relations.
The Agent decides what to look up; application code validates tool requests, records failures, and formats the answer.

Abstract

Maple Chat is a local-first Korean assistant for a configured Discord community. Its default Agent path plans a question, selects schema-validated read-only tools, evaluates their results, and returns an answer. Tools provide stored community evidence, official updates, exact knowledge-graph relations, deterministic experience calculations, and optional character information.

The alternative QA path combines BGE-M3 dense retrieval with lexical search, Reciprocal Rank Fusion, BGE-Reranker scoring, and reviewed entity relations in PostgreSQL. Generation uses a local OpenAI-compatible service; the current deployment uses TensorFold serving under the application model alias local-coder. No part of this architecture makes every generated statement automatically correct.

This page describes the implementation inspected on 17 November 2026. The Korean examples below are actual application-level runs using the deployed chatbot engine, current model, and stored data—not hand-written demonstration answers or a new accuracy benchmark.

Service Requirements

  • Controlled entry: accept direct mentions only in configured Discord servers and channels; reject bot/webhook traffic and invalid or oversized questions.
  • Evidence appropriate to the question: search documents for community observations, use the graph for reviewed names and relations, and delegate supported numerical work to calculation tools.
  • Readable Korean answers: request an easy 1–3 sentence opening summary followed by the detailed explanation and its qualifications. This is a prompt instruction, not a sentence-count validator.
  • Explicit failure and bounded execution: validate JSON/tool arguments, limit tool calls and retries, suppress duplicate message responses, and record resumable Agent checkpoints.
  • Traceability: retain the source links used by QA and the Agent execution/tool record. QA source buttons and Agent attribution are different mechanisms.
  • Operational limits: per-user and per-channel rate limits, serialized generation, a bounded admission counter, and token/time diagnostics. There is no newly claimed latency or availability SLA.

Recent conversation context is injected into the Agent path: up to five turns with a one-hour TTL and shortened previous answers. The current QA path does not receive the same context. Job-guide and combat-rotation construction remains paused; the presence of a guide lookup tool does not imply complete or current guide coverage.

Why Retrieval, and Why a Knowledge Graph?

Document evidence and domain relations solve different problems. Neither replaces the other.

Retrieval: find what a source actually says

A question about equipment investment or player experience needs passages from stored discussions—not a plausible answer recalled from model weights. Dense and lexical candidates are fused and reranked so the model can inspect a bounded set of relevant sources.

Retrieval returns observations, not universal rules. A question, failed attempt, historical patch, and successful report must not be treated as interchangeable evidence.

See the live community-search example and its observed tool trace.

Graph: keep a name attached to the right entity

Similar text cannot by itself establish a class relation or disambiguate a shared name. The graph stores explicit triples: Xenon belongs to both Thief and Pirate; the Destiny weapon and Destiny content mode are separate entities.

Alias matching and stored relations provide a canonical reference. They do not automatically supply boss tactics, skill rotations, or current community consensus.

Before the model

  1. Entry and context: strip the bot mention, parse options, check access/length/rate limits, and construct Agent conversation context.
  2. Agent route: generate and validate a plan, then provide the tool catalog and schemas. Each tool result is data for the next decision—not an instruction to execute.
  3. QA route: identify graph aliases, embed the query, retrieve dense and lexical candidates in parallel, fuse/rerank them, and separate factual claims from question-only context. Graph lookup and query embedding in the hybrid retriever are sequential.
  4. Prompt assembly: keep canonical relations, untrusted source text, provenance, and the user question distinguishable. Do not invent unsupported abbreviation expansions.

Model transport

The client requests temperature 0.1, thinking disabled, an output-token budget, and SSE usage reporting. It collects the streamed result before Discord output. Agent plan/action/forced-final budgets are 512/768/1024 output tokens; ordinary finish decisions share the action budget. QA defaults to 1024. These are current code limits, not a measured latency guarantee.

After the model

  1. Agent: parse the plan/action JSON and validate its schema; execute only registered tools with valid arguments; block repeated identical tool calls; checkpoint results and distinguish failed runs from success.
  2. QA: stop without generation when both document and graph evidence are absent. Check unsupported term expansions, attempt one repair generation, and fall back to retrieved facts when generation is unavailable or repair remains invalid.
  3. Output: add the applicable attribution, execution/source record and processing metrics; neutralize mentions and split long Discord messages. QA source inspection is requester-only and expires by default after seven days.

Route selection: Agent is the default. --qa --rag-mode mix selects mixed QA retrieval; --qa --no-rag selects direct QA generation. --no-rag alone does not prohibit the default Agent from choosing a search tool.

Knowledge Graph: Stored Relations, Not Guessed Links

A small subset of actual stored triples, with presentation labels in English. Arrows retain their database predicate and direction; no similarity or inferred edges are added.

The graph snapshot at 15:34 KST on 17 November 2026 contains 217 entities, 292 relations, 755 aliases and 7 sources. Aliases are lookup labels, not 755 additional semantic entities. Sources retain versions and provenance.

Knowledge graph relations and community thread links are different structures. A reply-to or has-comment link supplies conversational context; it does not prove agreement, contradiction, or truth. Document retrieval remains necessary for the experiences and procedures that the graph does not contain.

Operations, Privacy & Known Boundaries

  • Local generation: the configured generator and TEI encoders remain inside the approved local service boundary. Optional character lookup is a separate NEXON API integration, not a local model.
  • Data handling: supported sensitive identifiers in collected text are masked and user identifiers are pseudonymized. Agent runs retain question text and tool arguments/results; session storage retains conversation text. Hashing an identifier does not mean no raw text is stored anywhere.
  • Availability: an active Discord process is not proof that generation is ready. The existing indexing wrapper can yield model memory and restore the mia-qwen profile afterward. No service or model configuration was changed for this page.
  • Remaining gap: QA term checks and source buttons do not apply identically to Agent answers. The Agent prompt still permits general gameplay guidance when a guide is missing, so evidence-only procedural answers are not guaranteed.
  • Freshness: date and official-source boosts help ranking but do not certify current-patch correctness. The graph and corpus totals are dated snapshots, not live counters.
