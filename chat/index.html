Maple Chat is a Discord RAG system that retrieves community experience from Inven, official updates from Nexon, and reviewed domain relations before generating locally with Qwen.

01 / Overview

Retrieval finds evidence.
The graph keeps it in scope.

Vector similarity can find a relevant post, but it cannot guarantee that a class, boss, abbreviation, or content mode has been linked to the correct entity. Maple Chat treats evidence retrieval and entity integrity as separate system responsibilities.

01 · Discover

Find relevant experience

Dense and lexical retrieval surface guides, reports, and comments even when the wording differs.

02 · Constrain

Keep the entity fixed

Jobs, bosses, difficulties, and modes are resolved as entities before evidence enters the answer context.

03 · Explain

Preserve evidence boundaries

Official facts, community experience, and contradictory reports remain distinguishable in the final answer.

02 / Pipeline

How one question becomes an answer

Each stage has an explicit boundary and can fail independently. If evidence is insufficient, the system declines to answer rather than relaxing those checks.

  1. 01
    Collect

    Collect within the approved scope

    Separate collectors fetch posts and comments from seven approved boards plus official patch notes.

    GET only
  2. 02
    Sanitize

    Remove personal data before storage

    Email addresses and phone numbers are masked; usernames are transformed with a salted HMAC.

    PII boundary
  3. 03
    Index

    Preserve source structure

    Chunks retain titles, boards, question context, and comment roles before BGE-M3 creates 1,024-dimensional vectors.

    pgvector
  4. 04
    Retrieve

    Search by meaning and wording

    RRF combines dense and pg_trgm rankings; a BGE cross-encoder selects the final evidence.

    Top 8
  5. 05
    Ground

    Resolve exact domain relations

    Jobs, bosses, abbreviations, and modes are traversed in the graph to block evidence from a different entity.

    Exact graph
  6. 06
    Generate

    Generate locally with provenance

    Trusted graph facts and untrusted evidence are passed separately; used sources and token telemetry are recorded.

    Local Qwen

06 / Quality loop

Turn production failures
into system requirements

Each observed failure is recorded with its cause, system-level response, validation evidence, and remaining risk.

01
Inconsistent procedure

Equivalent questions, conflicting procedures

The system reused assumptions from question posts as if they were supported answer claims.

Resolution

Separate question context from answer-bearing comment claims

02
Terminology drift

An abbreviation expanded to the wrong item

Free-form generation invented a canonical name for a domain abbreviation.

Resolution

Validate abbreviation relations, then regenerate or use graph fallback

03
Entity collision

Evidence crossed between two bosses

Similar boss contexts pulled records from the wrong entity into the answer.

Resolution

Require both job and boss scope, backed by official boss variants

04
Polysemy

A shared name hid the boss mode

One surface form referred to both an item and a boss mode, creating an unresolved ambiguity.

Resolution

Link multiple entities to one span and traverse relations by context

Failure-driven contract

Define the failure → separate cause from evidence → design a general fix → add regression coverage → revalidate in operation → record remaining risk
